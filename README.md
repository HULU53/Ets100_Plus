E+ 是一个面向 e听说（ETS100）的本地、云端与自动化研究工具。

它可以读取 e听说客户端已经下载到手机里的作业数据，也可以通过 ETS100 云端接口登录并获取作业列表，再把试卷、题目、原文和答案整理成更易阅读的页面。

## 🎯 这个项目能做什么

- 读取 e听说本地作业数据，并解析试卷、分区、题目、原文和答案。
- 支持 Direct Read、Shizuku、Root 和云端四种使用方式。
- 支持云端账号密码登录和讯飞网页登录。
- 支持当前作业和历史作业列表，并可按作业下载、解析和缓存。
- 适配广东初中、广东高中、北京初中、北京高中及通用试卷结构。
- 支持模仿朗读、听说信息、问答信息、信息转述、询问信息等题型。
- 支持试卷详情查看、答案复制、导出图片和分享。
- 内置实验性的自动化悬浮窗、无障碍页面读取、OCR、选项定位和 TTS 朗读。
- 答案详情页可以将当前试卷一键生成悬浮窗任务队列。
- 支持主题配色、深色模式、动态取色、主界面图标颜色和返回动画。
- 支持 Material 与 Miuix 两套根主题，首页、设置、主题、底部导航和读取页均已接入 Miuix。
- 首页显示激活状态、无障碍状态、应用启动次数和累计已读取文件数。

## 📱 系统要求

- Android 13 及以上（`minSdk = 33`，与应用使用的 Miuix Blur 模块要求一致）。
- 应用包名为 `com.hulu.etsplus`。
- 读取本地数据时，需要设备已经安装 e听说客户端 `com.ets100.secondary`。
- 云端模式需要网络连接和 ETS100 账号。
- 首次启动和后续启动会联网读取公告与远程配置。当前实现中，远程配置请求失败会提示网络异常并退出应用。
- 如果从旧的 `Fe` 版本升级，由于包名已经改变，Android 会把它视为一个全新的应用，旧应用的数据和系统授权不会自动迁移。

## 🚀 第一次使用

1. 安装并打开 E+。
2. 阅读并同意“使用守则与法律声明”。
3. 进入“设置” → “运行授权”。
4. 按需完成“全文件访问”“悬浮窗权限”“应用列表权限”。
5. 在运行授权页选择一个工作模式。
6. 返回“答题”页读取本地或云端试卷。
7. 点击试卷查看答案详情。

## 🔑 四种工作模式

| 模式 | 工作方式 | 主要条件 | 适合场景 |
|------|----------|----------|----------|
| 云端模式 | 登录 ETS100 接口，在线获取作业列表并下载资源 | ETS100 账号、网络 | 本地没有完整作业数据，或想直接查看云端作业 |
| Direct Read | 通过全文件访问或零宽字符路径读取 e听说数据目录 | 全文件访问或设备支持漏洞直读 | 想直接读取手机中已经下载的作业 |
| Shizuku | 通过 Shizuku 执行文件访问命令 | 安装并运行 Shizuku，授予本应用权限 | 不想 Root，但需要稳定的系统级文件访问 |
| Root | 通过 Root 命令直接读取数据目录 | 设备已 Root，并授予 Root 权限 | 设备已经 Root，需要最高权限 |

当前版本的首页“已激活”状态会综合检查基础权限和目标模式是否真正可用。云端接口本身不依赖本地文件路径，但为了保持首页状态、悬浮窗和自动化功能正常，建议先完成基础权限授权。

### ☁️ 云端模式

云端模式不会读取手机里的 e听说数据目录，而是：

1. 使用 ETS100 账号登录。
2. 获取账户信息和作业列表。
3. 下载作业压缩包。
4. 生成解压密码并解压资源。
5. 读取 `content.json` 并解析题目与答案。
6. 将作业列表、下载状态和解析结果缓存到本机。

云端模式支持：

- 账号密码登录。
- 讯飞网页登录。
- 自动设备绑定。
- 当前作业和历史作业切换。
- 作业下载进度显示。
- 下载失败后的单独重试。
- 本地缓存和缓存清理。

**重要风险：**

- 云端登录可能导致 E听说官方客户端退出登录。
- 开始云端读取前，请确认没有正在进行的练习、录音或考试。
- 建议先读取并查看答案，再去 E听说官方客户端做题。
- 讯飞网页登录的 Token 失效后，当前实现会要求重新进行讯飞登录，不会自动使用密码重新登录。
- 登录信息、Token、账户 ID、机器码和密码会保存在本机 SharedPreferences 中，请勿在不可信设备上登录。

### ✨ Direct Read

Direct Read 会尝试直接访问：

```text
/storage/emulated/0/Android/data/com.ets100.secondary/files/Download/ETS_secondary
```

主要目录包括：

- `data/`：常规试卷数据。
- `resource/`：按资源包组织的作业、题目和答案数据。

Android 10 及以下可以直接使用常规路径。Android 11 及以上会优先检查全文件访问权限，并尝试可用的零宽字符绕过路径。运行授权页提供“测试漏洞直读”按钮，可以直接检查当前设备是否支持。

如果提示不支持：

- 尝试授权“全文件访问”。
- 改用 Shizuku 或 Root。
- 或者使用云端模式。

### 🧩 Shizuku

1. 安装并启动 [Shizuku](https://shizuku.rikka.app/)。
2. 回到 E+，进入“设置” → “运行授权”。
3. 选择 Shizuku 模式。
4. 点击授权按钮，并在系统弹窗中允许请求。
5. 返回“答题”页读取数据。

Shizuku 通过系统服务执行目录扫描、文件读取和删除命令，因此比普通应用文件访问更稳定，但依赖 Shizuku 服务持续运行。

外部包名 `moe.shizuku.privileged.api` 不能修改，否则将无法打开或检测 Shizuku。

### 🔓 Root

1. 确认设备已经正确 Root。
2. 进入“设置” → “运行授权”。
3. 选择 Root 模式。
4. 在 Root 管理器中授予 E+ Root 权限。
5. 返回“答题”页读取数据。

Root 模式会通过 `su` 执行文件读取和系统操作。不同设备的 Root 实现、命令兼容性和授权弹窗可能不同。

## 📚 读取和查看答案

### 本地读取

选择 Direct Read、Shizuku 或 Root 后，答题页会：

1. 检查当前模式是否可用。
2. 扫描 `data/` 和 `resource/` 目录。
3. 先显示试卷摘要列表。
4. 在后台继续解析完整答案。
5. 将解析结果缓存，切换页面或重启应用后可以恢复。

本地读取不会上传手机里的试卷文件。

### 云端读取

1. 进入“设置” → “运行授权”。
2. 选择“云端模式”。
3. 使用 ETS100 账号密码或讯飞网页登录。
4. 返回“答题”页。
5. 点击右下角“读取”。
6. 确认风险提示后，等待云端作业列表加载。
7. 在“当前作业”和“历史作业”之间切换。
8. 点击一个作业开始下载和解析。
9. 下载完成后，再次点击作业查看答案。

### 试卷详情

试卷详情页会按题型分区展示：

- 朗读原文。
- 选择题及选项。
- 问答信息。
- 信息转述。
- 询问信息。
- 其他可解析的标准答案内容。

复制或导出时会使用统一落款：

```text
E+守护你的答案
```

### 导出与分享

- 可以将答案复制到剪贴板。
- 可以将试卷导出为 PNG 图片。
- 图片会保存到系统“图片/E+”目录。
- 导出文件名前缀为 `EPlus_Answer_`。
- 导出完成后会打开系统分享面板，注意在某些系统上会被阻止，届时将会自动存储在相册中。

### 删除数据

答题页提供删除入口：

- 本地模式会删除 e听说目录中的 `data/` 和 `resource/` 内容。
- 云端模式会删除 E+ 缓存下来的云端作业数据。
- 删除操作不可撤销，请先确认数据已备份。

## 🪟 自动化悬浮窗

自动化功能属于实验性研究模块，入口位于：

```text
设置 → 悬浮窗设置
```

它不会改变原有的本地或云端答案读取流程，而是从已经解析成功的试卷中选择题目，生成任务队列，再由悬浮窗控制执行。

### 使用前准备

1. 在“悬浮窗”页面授予悬浮窗权限。
2. 启用“自动化无障碍服务”。
3. 可选的“屏幕捕获备用通道”用于无障碍截图不可用时降级到 MediaProjection。
4. 点击“选择答案”，从已经读取成功的本地或云端试卷中选择题目和答案版本。
5. 配置悬浮窗尺寸、透明度、贴边间距、停靠方向和拖动锁定。
6. 点击“显示悬浮窗”，再点击“开始”。

### 任务队列

- 有答案的题目才能生成自动化任务。
- 每道题可以选择本次使用的答案版本。
- 选择题和朗读题会自动使用不同任务类型。
- 当前任务完成后会自动切换到下一题。
- 下一题会停在“已就绪”状态，需要再次点击“开始”。
- 最后一题完成后会停止任务队列。
- 执行失败时会进入错误状态，不会继续盲目点击后续题目。

### 从答案详情页一键生成任务

答案详情页右上角新增“悬浮窗任务”图标按钮，位于原“更多操作”按钮左侧。点击后：

1. 只处理当前正在查看的试卷。
2. 自动遍历该试卷的全部题目。
3. 跳过没有答案的题目。
4. 每道题默认选择第一个答案版本。
5. 如果旧任务正在运行，会先停止并隐藏旧悬浮窗。
6. 使用新任务替换旧队列，并进入“已就绪”状态。
7. 自动跳转到“设置” → “悬浮窗设置”页面。

这个入口不会自动显示悬浮窗，也不会自动开始第一题。当前试卷没有可用答案时，只会提示，不会修改旧队列或跳转页面。

### 选择题执行流程

每个选择题任务大致按照以下顺序执行：

1. 截取当前屏幕。
2. 优先读取无障碍节点文字。
3. 节点文字不足时使用 ML Kit 中文 OCR。
4. 比较当前页面题目与任务题目。
5. 在识别结果中定位正确选项。
6. 执行点击。
7. 成功后切换到下一题。

点击顺序为：

1. 查找目标坐标处最小、可用的可点击无障碍节点。
2. 节点点击失败时派发坐标手势。
3. 无障碍手势不可用时，尝试通过 Shizuku 或 Root 执行 `input tap`。

为防止误点：

- 会先检查题目是否匹配。
- 会过滤屏幕外或无效坐标。
- 相似度低于阈值时不会点击。
- 坐标手势必须等待系统回调成功。
- 负数或无效坐标会被直接拒绝。

### 朗读任务

- 使用系统 TextToSpeech。
- 默认优先使用简体中文。
- 中文语音不可用时尝试系统默认语言。
- 朗读完成后自动切换到下一题并等待用户开始。
- “停止”可以立即停止当前朗读。
- 可选的音频增强会尝试提高媒体音量并保持扬声器路由，朗读结束后恢复原状态。

当前没有使用在线 AI 语音，也没有生成 PCM/WAV 或虚拟麦克风。

## 🖼️ 截图、OCR 与无障碍

自动化模块优先使用无障碍服务：

- 读取当前页面的可见文字和屏幕坐标。
- 忽略悬浮窗自身覆盖的区域。
- Android 11 及以上优先使用无障碍截图。
- 无障碍截图不可用时，才降级到 MediaProjection。

MediaProjection：

- 只在任务请求时转换单帧，不会持续把每一帧都转换成 Bitmap。
- 两次截图之间至少间隔 1000 毫秒。
- 单次截图等待超时为 1500 毫秒。
- 同一时间只允许一个截图请求。
- 截图后会涂黑悬浮窗区域，避免 OCR 识别到悬浮窗文字。

OCR 使用 ML Kit 中文文字识别。识别时会优先使用无障碍节点，节点文字不足时再把节点文字与 OCR 结果合并。

## 📝 自动化日志

自动化模块默认开启日志。

- Logcat 标签：`FeAutomation`
- 内存日志最多保留 300 条。
- 悬浮窗页面显示最近 12 条日志。
- 文件日志位置：`/storage/emulated/0/Download/fe_test.txt`
- 文件最多保留约 100 万个字符，超出后删除最旧内容。
- 未捕获的 Java/Kotlin 异常和协程异常会记录堆栈、线程、设备、版本和当前任务。
- 应用下次启动时会尝试读取 Android 保存的 Java 崩溃、Native crash、ANR、低内存和异常退出记录。
- 如果系统提供 trace，会把完整 trace 写入 `fe_test.txt`。
- 历史退出记录包含退出原因、进程名、时间、设备信息和简单内存数据。
- 已增加重复记录保护，避免每次启动重复写入旧崩溃。

Native crash 发生时应用进程已经退出，无法当场写文件，只能在下次启动补录。ANR、Native crash 和系统强制终止记录仍然可能受系统日志保留时间限制。

为降低敏感信息泄露风险：

- 日志不会保存完整答案。
- 日志不会保存完整 OCR 文本。
- TTS 只记录文字长度。
- 任务标题和命令输出会限制长度。

可以在“设置” → “其他选项” → “自动化日志”中关闭日志。关闭后会停止写入 Logcat、内存日志、`fe_test.txt` 和新的崩溃堆栈。

## 🔐 权限说明

| 权限 | 用途 |
|------|------|
| 全文件访问 | 读取 e听说在 `Android/data` 中的作业数据 |
| 悬浮窗 | 显示自动化控制面板 |
| 应用列表 | 检查 e听说、Shizuku 等外部应用信息 |
| 无障碍 | 读取页面文字、执行节点点击和坐标手势 |
| 屏幕捕获 | 无障碍截图不可用时提供备用截图通道 |
| 网络 | 云端登录、作业列表、公告和远程配置 |
| 通知与前台服务 | 保持自动化悬浮窗和媒体投影服务运行 |

无障碍服务只有用户手动在系统设置中启用后才会连接。只勾选设置但没有成功连接时，应用不会把它显示为已激活。

## 🎨 主题与个性化

主题设置支持：

- Material 和 Miuix 两种根主题。
- 8 套彩色主题。
- 日间、夜间和跟随系统模式。
- Android 12 及以上从壁纸提取动态主题色。
- 主界面图标颜色自定义，支持 `#RRGGBB` 格式。
- 缩放、渐变、滑动和关闭预见性返回动画。
- “界面模糊（实验性）”开关，默认开启，并使用 `blur_enabled` 保存状态。

Miuix 已接入核心 UI、图标、Preference、Navigation 和 Blur 模块。首页、设置页、主题设置页、底部导航和读取页均已完成 Miuix 迁移；读取页统一使用 Miuix 渲染，原有答案解析、业务数据和导出图片逻辑保持不变。答案详情页 Miuix 顶部栏已预留 `WindowInsets.statusBars`，避免返回按钮、标题和操作按钮进入系统状态栏区域。

模糊效果目前仍属于实验性功能。此前设置页和主题设置页顶部栏的模糊会形成自引用图形层，可能触发 Android HWUI 原生栈溢出，因此这两个页面已经移除实际模糊；首页方案也暂时停止继续调优。模糊开关和入口继续保留，但当前不应把它视为稳定的视觉效果。

主界面图标颜色只影响首页顶部图标，不会修改桌面应用图标。浅色背景会自动使用深色图形，避免白色图标看不清。

## 🏠 首页与统计

首页包含：

- 当前激活状态。
- 无障碍服务连接状态。
- 应用冷启动总次数。
- 累计成功读取的唯一文件数。
- 远程公告和更新日志入口。

应用统计保存在应用私有目录：

- 清除应用数据或重新安装后，启动次数和文件统计会重置。
- 重复读取同一个文件不会重复增加文件数。
- 读取失败的目录或文件不会计入统计。

远程配置源位于：

```text
https://hulu53.github.io/Eplus/api/app/config.json
https://hulu53.github.io/Eplus/api/app/config
```

远程配置支持公告、更新日志和 KillSwitch。KillSwitch 开启时，应用会显示“程序异常”并退出。

## ⚠️ 当前限制

- 没有多帧 OCR 稳定性检测。
- 没有点击后的页面变化验证。
- 没有自动检查答题结果或正确率。
- 错误点击前没有二次确认。
- 没有检测目标应用是否真正进入录音状态。
- 没有处理蓝牙音频路由。
- 系统 TTS 能否被目标应用采集，取决于设备回声消除、降噪和音频策略。
- Root/Shizuku 音频命令的兼容性取决于设备和 Android 版本。
- MediaProjection 会话目前不能持久恢复。
- 云端 Token 可能过期，讯飞登录失效后需要重新登录。
- Miuix 界面模糊仍处于实验阶段，设置页、主题设置页和首页目前没有稳定的实际模糊效果。
- Native crash、ANR 和系统强制终止记录依赖 Android 后续保留的历史日志，可能被系统清理。
- e听说客户端更新后，数据格式、接口或目录结构可能发生变化。

## 🧭 源码导览

主要代码位于 `app/src/main/java/com/hulu/etsplus/`：

- `ActivationScreen.kt`：运行授权、基础权限和模式选择。
- `ReadScreen.kt`：本地与云端读取、作业下载、答案查看、导出和删除。
- `ETS100FileReader.kt`：Direct Read、Shizuku、Root 文件读取器。
- `ETS100AnswerReader.kt`：试卷、分区、题型和答案解析。
- `ETS100ApiClient.kt`：ETS100 登录、账户、作业列表和文件下载接口。
- `ETS100AuthManager.kt`：云端登录信息和机器码存储。
- `AutomationFoundation.kt`：任务、会话状态和模块注册。
- `AutomationOrchestrator.kt`：自动化任务执行流程。
- `AutomationOverlayService.kt`：自动化悬浮窗和前台服务。
- `AutomationAccessibilityService.kt`：无障碍文字读取、截图和点击。
- `MlKitTextRecognitionSource.kt`：ML Kit 中文 OCR。
- `OptionLocator.kt`：题目匹配、选项定位和点击坐标计算。
- `MediaProjectionCaptureSource.kt`：屏幕捕获备用通道。
- `AutomationSpeechOutput.kt`：系统 TTS 朗读。
- `AutomationCrashHandler.kt`：未捕获异常和下次启动时的历史退出信息补录。
- `ThemeManager.kt`、`ThemeSettingsScreen.kt`：主题、配色和个性化设置。
- `MiuixThemeBridge.kt`：Material 主题颜色到 Miuix `ThemeController` 的映射。
- `ReadMiuixCompat.kt`：读取页的 Miuix 统一渲染兼容层。
- `RemoteConfigManager.kt`、`RemoteContentActivity.kt`：远程公告、更新日志和 KillSwitch。
